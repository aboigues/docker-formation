# 🎫 INC-101 — « La recherche par catégorie rame »

| Priorité | Ouvert par | Service | Statut |
|---|---|---|---|
| 🟠 P2 — dégradé | Support client | Telemach Shop — API catalogue | Ouvert |

## Ce qu'on nous dit

> « Depuis la mise en prod, quand je clique sur une catégorie (Jardin, Cuisine…), la page met une éternité à s'afficher. La fiche d'un produit, elle, s'ouvre tout de suite. Les clients se plaignent sur les réseaux. »
> — Camille, support client

## Ce qu'on sait

- La boutique est ouverte : `loadgen` envoie du trafic en continu.
- Aucune erreur n'est remontée : tout « marche », mais lentement.
- Le catalogue contient **1 million de produits**.

## ✅ Critère de clôture

1. La latence p95 de la route `GET /products` redescend sous **50 ms** dans Grafana.
2. Le correctif **survit à une réinstallation** : une base recréée de zéro n'a plus le problème.

---

## 💡 Indices (ouvrez-les un par un)

<details>
<summary>Indice 1 — Où regarder ?</summary>

Grafana → dashboard **Telemach Shop — production**, panneau **Latence p95 par route**. Quelle route se détache ? Puis le panneau de logs, en bas : l'API journalise les **requêtes SQL lentes** (`level=WARN`).

Dans **Explore** (source Loki), essayez :

```logql
{service="tp14_shop-api"} | json | msg="requête SQL lente"
```
</details>

<details>
<summary>Indice 2 — Quoi ?</summary>

Le problème est dans la base, pas dans l'API. Demandez à PostgreSQL **comment** il exécute la requête de l'API (lisez-la dans `app/main.go`, `handleProducts`) :

```bash
docker exec -it $(docker ps -q -f name=tp14_db) psql -U shop -d shop
```
```sql
EXPLAIN ANALYZE SELECT id, name, category, price, description FROM products
WHERE category = 'cat-07' ORDER BY price DESC LIMIT 100 OFFSET 0;
```

Repérez le `Seq Scan` et le nombre de lignes lues (`Rows Removed by Filter`).
</details>

<details>
<summary>Indice 3 — Le correctif</summary>

Un **index** qui sert à la fois le filtre (`category`) et le tri (`price DESC`) :

```sql
CREATE INDEX idx_products_category_price ON products (category, price DESC);
```

1. Appliquez-le **à chaud** dans `psql` : relancez l'`EXPLAIN ANALYZE` (`Index Scan`, quelques ms) et regardez le p95 chuter dans Grafana.
2. Rendez-le **pérenne** : ajoutez la même ligne dans `db/init.sql`, sinon le prochain environnement (ou la prochaine restauration) retrouvera le problème.

> 🧠 `db/init.sql` n'est exécuté qu'au **premier** démarrage, sur un volume vide. Une base déjà en service ne le relit jamais : d'où le correctif « à chaud » **et** « dans le code ».
</details>
